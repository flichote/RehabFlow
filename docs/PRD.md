# RehabFlow（康复流程流）产品需求文档（PRD）

- 版本：v1.0（初版）
- 状态：待评审
- 配套文档：`docs/design/design-system.md`、`docs/design/pages.md`、`docs/design/components.md`、`docs/design/flows.md`
- 更新日期：2026-08-05

> **产品一句话**：把「康复计划」从纸面变成可执行、可追踪、可预警的院内排课闭环。
> **与 CCN 的关系**：独立项目。CCN 管院外康复管理，RehabFlow 管**院内康复治疗执行**（排课引擎、软打卡、主任看板）。
> **与 HIS 的关系**：RehabFlow **独立于医院现有 HIS 系统运行**——独立数据库、独立账号体系、独立部署，不读 HIS 库、不调 HIS 接口、不依赖 HIS 登录（详见 `docs/architecture.md` §9）。

---

## 1. 产品背景与目标

### 1.1 业务背景

医院康复科日常运转依赖排课与执行：康复师有固定治疗时段，患者需要在 PT/OT/ST 治疗室之间流转。传统方式（纸质排班、口头通知、微信群）存在三大痛点：

1. **排课靠人工协调**：冲突频发（患者同时段两节课、康复师时间重叠），发现晚、处理慢。
2. **患者位置不可知**：主任/医生无法实时知道"患者此刻在哪"，催课、找人靠打电话。
3. **执行无数据**：课程是否真的上了、课时消耗多少、谁缺席了，全靠事后回忆，无法支撑管理决策。

### 1.2 产品目标

| 目标 | 衡量方式 |
| :--- | :--- |
| 排课冲突趋零 | 冲突在排课时即被检测，不允许静默产生 |
| 患者位置实时可见 | 软打卡机制下，任一时刻可查询患者当前所在位置 |
| 课程执行可追溯 | 每节课有实际开始/结束时间、课时消耗、完成/缺席状态 |
| 异常可预警 | 超时未开始、缺席、冲突未处理 → 主任看板实时警报 |
| 管理有数据 | 看板支撑：工作量、患者分布、课程趋势、出勤率 |

### 1.3 目标用户

| 角色 | 说明 | 核心诉求 |
| :--- | :--- | :--- |
| 排课管理员 / 主任 | 负责全院排课与资源调度 | 高效排课、无冲突、全局视图 |
| 康复师 | 执行课程的治疗师（PT/OT/ST 组） | 课表清晰、操作快（一键开始/结束）、记录方便 |
| 主管医生 | 负责患者康复方案 | 患者 360° 视图、评估趋势、位置修正 |
| 科室主任 | 管理决策者 | 数据看板、异常预警、工作量分析 |
| 患者 | 接受康复治疗 | 接收上课提醒、查看自己的课程安排 |

## 2. 核心业务状态机设计

系统的灵魂在于「患者状态」和「课程状态」的流转，这是决定"患者此刻在哪里"的关键。

### 2.1 患者院内状态流转

```text
[入院] --> 病房(待评估) --> 评估中 --> 待排课 --> 课程执行中 --> 课程结束(回病房/继续下一节) --> 出院
```

**状态定义**：

| 状态 | 说明 |
| :--- | :--- |
| 在病房 (Ward) | 未开始今日治疗，或治疗结束已返回 |
| 前往途中 (En Route) | 系统已提醒，患者正在前往治疗室（可做 Gap 提醒） |
| PT/OT/ST 治疗中 (Treating) | 康复师在系统点击「开始上课」后锁定 |
| 临时暂停 (Paused) | 患者因身体不适暂停治疗（需康复师操作） |
| 旷课/缺席 (Absent) | 患者未在规定时间到达（康复师可标记） |

### 2.2 单个课程实例的状态机

```text
[待执行] --> [提醒已发] --> [进行中] --> [已完成] / [未完成-请假] / [未完成-缺席]
```

**关键操作点**：

- 康复师点击**「开始上课」**：状态变为"进行中"，系统记录实际开始时间。
- 康复师点击**「结束上课」**：状态变为"已完成"，系统记录实际结束时间，并自动计算课时消耗。
- 若康复师未点击开始，系统在课程时间结束后**自动标记为"异常"**，并在主任看板生成警报。

## 3. 页面功能细化（含交互逻辑）

### 3.1 排课日历页（核心排课引擎）—— 面向排课管理员/主任

**界面布局**：左侧为资源列表（康复师/治疗室），右侧为时间轴网格。

| 要素名称 | 细化说明 | 交互逻辑 |
| :--- | :--- | :--- |
| 资源筛选器 | 下拉筛选：全部康复师 / PT组 / OT组 / ST组 | 切换视图仅显示对应组别的排课 |
| 时间维度切换 | 日 / 周 / 月 视图 | 默认周视图，周一为起始日 |
| 课程卡片 | 卡片上显示：患者姓名、课程类型(PT/OT/ST)、课程时长 | 卡片颜色区分：蓝色-PT，绿色-OT，橙色-ST |
| 拖拽排课 | 从"待排患者池"拖拽至时间网格 | 松手时触发**冲突检测**（检测1：该患者此时是否有课；检测2：该康复师此时是否有课） |
| 冲突弹窗 | 若检测到冲突，弹窗提示"该时间段已被占用，是否查看详情？" | 提供"强制替换"或"取消"按钮 |
| 空白时段 | 网格中未被占用的白色格子 | 双击空白格子，弹出"新建课程"抽屉表单 |
| 课程详情抽屉 | 右侧滑出面板 | 展示：课程详情、修改时间、取消课程、填写治疗记录入口 |

### 3.2 我的课表 (My Schedule) —— 面向康复师

**界面改版**：更偏向"日程清单"，非网格视图，以提高阅读效率。

| 要素名称 | 细化说明 | 交互逻辑 |
| :--- | :--- | :--- |
| 今日概览卡片 | 顶部显示：今日总课时、已完成节数、剩余节数 | 数字实时变动 |
| 时间线列表 | 按时间升序排列，每条显示：时间段、患者姓名、课程类型、治疗室 | 当前时间正在进行的课程**高亮边框闪烁** |
| 空闲时段标识 | 在两节课之间显示**"空闲 45分钟"**灰色标签 | 点击可快速添加临时课程 |
| 一键提醒 | 课程卡片上有一个"铃铛"图标 | 点击后向患者端 App/微信推送上课提醒（提前15分钟） |
| 治疗记录入口 | 课程卡片右侧"填写记录"按钮 | 点击弹出模态框，填写：本次治疗内容、患者反应、下次注意事项 |

### 3.3 患者 360° 视图 (Patient Profile) —— 面向主管医生/康复师

| 要素名称 | 细化说明 | 交互逻辑 |
| :--- | :--- | :--- |
| 患者基本信息区 | 姓名、年龄、诊断、入院日期、主管医生、责任康复师 | 展示固定信息 |
| 实时位置卡片 | 大号文字显示当前状态："当前位于：PT大厅2号床" | 状态变更时自动刷新，若在病房则显示"当前位于：住院部3楼5床" |
| 康复计划时间轴 | 展示入院以来的所有课程记录，按时间倒序排列 | 绿色点表示已完成，灰色点表示待执行，红色点表示缺席 |
| 本周课程一览 | 以小型周历展示本周7天的课程分布 | 点击某一天，下方展开该日的详细时间表 |
| 评估记录 Tab | 存放所有康复评估量表（如 Fugl-Meyer 评分、Barthel 指数） | 可查看历史评估趋势折线图 |

### 3.4 数据看板 (Dashboard) —— 面向科室主任

**主任看板布局（从左到右，从上到下）**：

| 位置 | 组件名称 | 展示内容 | 刷新频率 |
| :--- | :--- | :--- | :--- |
| 顶部 | 核心KPI卡片 | ① 今日在院患者总数 ② 今日已排课程总数 ③ 当前治疗中人数 ④ 康复师今日出勤率 | 实时 |
| 左侧 | 患者分布环形图 | 病房 vs PT大厅 vs OT大厅 vs ST室 的人数占比 | 实时 |
| 中间 | 治疗师工作量柱状图 | 横轴：康复师姓名；纵轴：今日课时数 | 每30分钟 |
| 右侧 | 异常预警列表 | 滚动显示：课程开始超时未执行 / 患者缺席标记 / 排课冲突未处理 | 实时推送 |
| 底部 | 近7天课程趋势折线图 | 展示本周每日课程总量的波动 | 每日更新 |

## 4. 位置追踪逻辑（软打卡，不依赖硬件）

由于医院难以做到每个房间安装蓝牙信标，系统采用**软打卡机制**：

| 触发动作 | 系统自动更新位置 |
| :--- | :--- |
| 康复师点击"开始上课" | 患者状态自动变为**"治疗中"**，位置变为对应的治疗室（如PT大厅） |
| 康复师点击"结束上课" | 患者状态自动变为**"在病房"**（逻辑预设为返回病房） |
| 主管医生在系统内手动修改 | 支持人工修正（当患者临时外出检查时使用） |
| 系统自动巡检 | 若课程结束后30分钟患者状态仍为"治疗中"，系统**发送提醒给康复师**确认是否忘记结束 |

## 5. 消息提醒系统 (Notification System)

| 触发事件 | 接收方 | 提醒方式 | 内容模板 |
| :--- | :--- | :--- | :--- |
| 新课程被安排 | 患者、康复师 | 站内信 + 可选短信 | "您已被安排 5月20日 14:00 PT课程，地点PT-1室" |
| 课程时间变更 | 患者、康复师 | 站内信 + 弹窗强提醒 | "您的课程时间已由14:00变更为15:00，请知悉" |
| 课程即将开始（提前15分钟） | 康复师、患者 | 浏览器弹窗通知 | "【提醒】您有一节课程将在15分钟后开始" |
| 康复师未点击开始（超时5分钟） | 康复师、主管医生 | 站内信 + 待办任务红点 | "您有一节10:00的课程尚未开始，请尽快确认" |
| 评估任务待办 | 康复师 | 待办列表出现 | "患者张三的入院评估尚未填写，已逾期1天" |

## 6. 技术实现补充建议

1. **时间精度**：所有课程时间以 **15分钟** 为最小粒度（即课程开始时间可为 9:00、9:15、9:30...）。
2. **并发处理**：排课冲突检测必须在**数据库事务**中完成，防止两个管理员同时排同一时间段造成数据脏读。
3. **数据权限隔离**：
   - 后端接口必须校验：医生只能查询 `Patient.doctor_id = current_user.id` 的数据。
   - 康复师只能查询 `Course.therapist_id = current_user.id` 的数据。
4. **缓存策略**：排课数据使用 Redis 缓存，减少数据库压力，但修改时必须同步更新缓存。
